# 隐私检查

## 两条边界

产品数据与源码分开。真实配置、凭据、数据库、日志、备份和内部工作记录不进入公开仓库。前端只接收状态 DTO，不能向主进程发送自由 Shell、SQL、路径或网络目标。

公开仓库采用干净的代码快照；历史工作区与原开发记录单独保留为私有，不通过改写历史假装旧 PR 已清除。

## 本地钩子

`npm run hooks:install` 只设置当前仓库的 `core.hooksPath`，记录当前 Node 可执行文件，避免误用系统里其他版本。pre-commit 检查 Git index，pre-push 检查每个待推送提交；删掉工作区文件不会清除已暂存的内容，后一次提交删掉秘密也不会抹掉前一次提交。

检查必须能运行 Gitleaks；缺失时停止，而不是静默跳过。输出只提供命中文件与规则，不打印秘密原值。`--no-gitleaks` 仅供隔离测试使用，常规钩子不使用它。

## 本机精确比对

可在项目根目录创建被忽略的 `.privacy.local.json`，仅登记外部私有文件的绝对路径：

```json
{
  "privateFiles": ["/absolute/path/to/private-profile.json"]
}
```

脚本在检查时读取这些文件里的常见私有字段进行精确比对，不把内容复制进仓库。它不能自动发现所有未知秘密；较短或常见的身份值、二进制、提交历史外的附件仍需人工核对。Gitleaks、Git ignore 和钩子也不能撤回已公开的内容。

## CI

CI 使用 GitHub 托管临时 runner 和只读 token，不连接本机、NAS 或生产配置。不使用 `pull_request_target`，不自动评论、上传秘密扫描报告或发布产物。Action 固定到审核时的提交版本。发布仓库前仍应单独检查全部历史与附属内容。
